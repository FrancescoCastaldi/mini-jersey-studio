# MiniJersey 3D Studio - Developer & Agents Context

This file serves as a knowledge base and changelog for AI agents and developers working on this project. It outlines the architecture, the technical constraints solved, and the latest modifications.

## 🎯 What the App Does (App Purpose)
**MiniJersey 3D Studio** is a fully client-side web application designed to allow users to create, customize, and visualize cycling jerseys (or generic T-shirts) in real-time. 

Core features include:
- **Visual Customization:** Users can change base colors, apply different geometric patterns, add text (like sponsor names or rider numbers), and upload custom images/logos to specific zones of the shirt.
- **Real-Time 3D Rendering:** As the user modifies the 2D design, the app instantly bakes the flat graphics into a dynamic texture and applies it to a realistic 3D model that the user can rotate and zoom in 360 degrees.
- **Custom 3D Model Upload:** Users can upload their own `.glb` or `.gltf` 3D models. The app automatically projects the custom 2D design onto the uploaded model.
- **Production Export (Tech Pack):** The app generates a manufacturing-ready "Tech Pack" — a flat 2D blueprint of the customized jersey that can be downloaded as an image or PDF for real-world printing and production.
- **Project Save/Load:** Users can save their current design state to a `.jersey` JSON file and import it later to resume work.

## 🏗️ Architecture Overview
- **Tech Stack:** Vanilla HTML5, CSS3, JavaScript. No bundlers (Webpack/Vite), no frameworks (React/Vue), no backend server.
- **Goal:** Run entirely client-side, directly from the file system (`file:///`), ensuring extreme portability.
- **Key Modules (`/js/`):**
  - `state.js`: Centralized state management using a publish/subscribe pattern. Handles all data (colors, texts, logos, patterns).
  - `app.js`: Main UI controller. Binds DOM events (sliders, inputs, buttons) and coordinates state updates.
  - `renderer.js`: 2D SVG Engine. Clones the flat SVG sewing patterns, injects user colors/logos/texts, and serializes them to HTML5 `<canvas>` via `XMLSerializer` and `Image`.
  - `three_viewer.js`: 3D WebGL Engine using Three.js. Loads the 3D model, sets up studio lighting, and applies the canvases generated by `renderer.js` as dynamic textures.
  - `techpack.js`: Handles the generation of the 2D production blueprints (Tech Packs) for printing/manufacturing.

## 🚀 Latest Major Modifications & Technical Solutions

### 1. 3D Model Loading & CORS Fix
- **Problem:** Browsers strictly block loading external files (like `.glb` models) via `XMLHttpRequest` or `Fetch` when the HTML is opened locally (`file:///`) due to CORS security policies.
- **Solution:** The default 3D model (`shirt.glb`, ~1MB) was converted to a Base64 Data URI and embedded directly into `js/model_data.js` as `window.SHIRT_GLB`. `THREE.GLTFLoader` natively parses Data URIs, bypassing CORS entirely.

### 2. Dynamic Planar UV Projection
- **Problem:** Every 3D model downloaded from the internet has its own unique UV mapping. Applying our custom flat SVG textures directly onto a random GLB model resulted in scrambled, distorted, or mirrored graphics.
- **Solution:** Instead of relying on the model's native UVs, `three_viewer.js` now implements **Dynamic Planar Projection**.
  - After loading, the code traverses all meshes and calculates the world-space bounding box.
  - It iterates through every vertex position (`geometry.attributes.position`).
  - Vertices facing front (`Z > 0`) are mapped to the left half of the texture (`u = 0.0` to `0.5`).
  - Vertices facing back (`Z <= 0`) are mapped to the right half (`u = 0.5` to `1.0`), and their horizontal coordinates are flipped so text reads correctly from the back.
  - The texture canvas was resized to `2048x1024` to accommodate the Front and Back renders side-by-side.

### 3. Custom 3D Model Import (.glb / .gltf)
- **Problem:** Users requested a highly specific, professional "Cycling Jersey" model (with 3 pockets, race-fit, and front zip). High-quality models of this specific garment type are not freely hot-linkable online and are protected by marketplaces (Sketchfab, TurboSquid). Procedural generation (`ExtrudeGeometry` / `LatheGeometry`) was deemed aesthetically insufficient by the user.
- **Solution:** Built an **Import Custom 3D Model** pipeline.
  - Added a file input in `index.html` (`#model-upload`).
  - Added logic in `app.js` to parse the uploaded file via `URL.createObjectURL(file)`.
  - Handed the blob URL to `threeViewer.loadModelFromURL(url)`.
  - Because of the Dynamic Planar Projection (see point 2), the user can upload *any* standard torso/shirt GLB model, and the app will instantly align the custom jersey graphics onto it perfectly.

### 4. Bounding Box & Scene Alignments
- **Problem:** Different models have different scales and origins, causing the "hanger" accessory to float or intersect incorrectly.
- **Solution:** The model is now dynamically centered and scaled to a strict normalized height (`2.8 units`) upon loading. The hanger's Y-position is calculated strictly against the model's normalized `boundingBox.max.y`.
